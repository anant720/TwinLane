# ADR 0004: Quarantine Reader Architecture and Selective Extraction

**Status**: Accepted  
**Date**: 2026-10-31  
**Authors**: Anant, Shweta, Aditya  

---

## Context
When an agent receives untrusted text (e.g., an email body, web scrape, or PDF), that content may contain indirect prompt injections. If the primary agent's LLM reads this text while having access to sensitive tools, the injected instructions can hijack tool execution.

Candidates considered:
1. **Mandatory Full Dual-LLM (CaMeL style)**: Every task step is duplicated across a privileged planner LLM and an unprivileged quarantined LLM.
2. **Text Filtering / Input Sanitization**: Attempting to scrub prompt injection text before passing it to the agent.
3. **Selective Quarantine Reader with Zero Tools & Schema Validation**: Quarantining untrusted data parsing, binding reader output to strict schemas, and ensuring plain-text outputs never promote to control.

## Decision
We chose **Selective Quarantine Reader with Zero Tools and Strict Output Schema Validation**.

### Rationale
1. **Zero-Tool Isolation**: The Quarantine Reader LLM is provisioned with **zero tool definitions**. Even if a prompt injection completely overrides its context or jailbreaks the model, it is impossible for the model to invoke external tools or APIs.
2. **Elimination of 2x Latency on Benign Control**: Unlike CaMeL, which forces a dual-LLM roundtrip for every single operation, TwinLane processes benign typed control messages directly through the deterministic Gate. The Quarantine Reader is only invoked when untrusted data must be ingested or summarized.
3. **Structured Schema Output**:
   - The Quarantine Reader is instructed and constrained to produce structured JSON conforming to a specific schema (e.g., summary fields, sentiment score, key entity extractions).
   - The Gate validates that the output matches the target schema and marks the output fields as `UNTRUSTED` or `EXTRACTED_UNTRUSTED`.
4. **Non-Promotion Invariant**:
   - Raw free-text strings generated by the Quarantine Reader remain tainted with `UNTRUSTED`.
   - The Gate strictly prevents free-text reader outputs from binding to control parameters of sensitive tools (e.g., email recipients, file paths, shell commands).

## Consequences
- **Positive**: Complete defense against tool hijacking from untrusted data; ~50% latency and cost savings compared to continuous dual-LLM execution for benign workflows; deterministic enforcement outside the model.
- **Negative**: If an attacker attempts text-only semantic distortion (e.g., causing the reader to write an inaccurate summary), the summary will still be inaccurate. This is addressed by transparent provenance tagging and display to the human user, not automated blocking.
