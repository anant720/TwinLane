# ADR 0001: JSON Serialization and RFC 8785 Canonicalization

**Status**: Accepted  
**Date**: 2026-10-31  
**Authors**: Anant, Shweta, Aditya  

---

## Context
TwinLane requires a deterministic wire format for message envelopes so that cryptographic signatures generated by a sender can be verified identically by any receiver across diverse runtimes and programming languages.

Two primary serialization candidates were considered:
1. **JSON with RFC 8785 (JSON Canonicalization Scheme - JCS)**.
2. **Binary Formats (CBOR with RFC 7049 deterministic encoding or Protocol Buffers)**.

## Decision
We chose **JSON with RFC 8785 (JCS)** as the primary serialization and canonicalization mechanism for TwinLane envelopes.

### Rationale
1. **Developer Ergonomics & Interoperability**: Modern LLM agents, tool interfaces (OpenAI function calling, Anthropic tool use, MCP), and HTTP transports natively operate on JSON. Choosing JSON eliminates transcoding overhead between application-level agent messages and wire envelopes.
2. **RFC 8785 Standard**: RFC 8785 defines a strict, unambiguous algorithm for normalizing JSON:
   - Object keys are sorted lexicographically by UTF-16 code units.
   - Whitespace outside of strings is eliminated.
   - Numbers are represented deterministically following ECMAScript / IEEE 754 standards without trailing zeros or ambiguous exponents.
   - Character escaping is standardized.
3. **Auditability & Observability**: Security operators and human supervisors can inspect raw wire envelopes in log streams, debugging proxies, and audit chains without specialized binary decoding tools.
4. **Performance**: In Python, pure-Python or C-accelerated canonical JSON serialization completes in under 0.1 ms for typical envelope sizes (< 100 KB), meeting sub-millisecond gate requirements.

## Consequences
- **Positive**: Seamless integration with existing agent ecosystems; human-readable wire traces; language-agnostic signature verification.
- **Negative**: Slightly larger wire payloads compared to CBOR/Protobuf. For large binary artifacts, payloads must either be base64-encoded or transferred out-of-band via `content_ref` with SHA-256 hash validation in the manifest.
