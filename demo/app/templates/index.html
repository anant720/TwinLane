TwinLane Architectural Reference & Formal Properties

TwinLane solves prompt injection at the wire layer: untrusted text can never formulate or authorize an execution command. Control is governed by cryptographic capabilities; untrusted data is confined and passive.

Message Delivery Pipeline
1. ORCHESTRATOR
Creates intent & signs with Ed25519 key
2. WIRE ENVELOPE
Separates Control Lane from Data Lane
3. WORKER AGENT
Processes untrusted data without authority
4. SECURITY GATE
7-step deterministic validation pipeline
5. AUDIT CHAIN
Immutable SHA-256 chained ledger
PROPERTY 1: AUTHENTICATION

All envelope senders are cryptographically verified against a Trust Store using Ed25519 public keys. Envelopes from unmapped principals are denied immediately.

PROPERTY 2: INTEGRITY

Envelopes are signed over RFC 8785 canonical JSON bytes. Any in-transit tampering with header, control lane, or data manifest invalidates the signature.

PROPERTY 3: REPLAY SAFETY

Cryptographically random 128-bit nonces with TTL caches prevent replay attacks. Monotonic session counters enforce strict message ordering.

PROPERTY 4: CAPABILITY CONFINEMENT

No action may execute without a signed, unexpired capability token explicitly authorizing the intent. Delegated child tokens may only attenuate privileges.
